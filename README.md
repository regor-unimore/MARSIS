The software and data in this repository are a snapshot of the software and data that were used in the research reported on in the paper "A Predict-then-Optimize Approach for the Research of Underground Water on Mars" by B. Ferrari, M. Delorme, M. Iori, M. Lippi and R. Orosei.

Important: This code is being developed on an on-going basis at https://github.com/regor-unimore/MARSIS. Please go there if you would like to get a more recent version or would like support.

***Description***
--

The material within the data and script folders is divided into "Machine Learning" and "Optimization", to better distinguish the two parts of the proposed predict-then-optimize approach:

```
data/
  ML - Data/               historical dataset (link), orbits to exclude, dataset for the future planning
  Opt - General Data/      general data files, used in combination with each instance
  Opt - Instances/         the 25 optimization instances (one .zip archive per instance)
results/
  Computational Results.xlsx   results reported in the paper
  experiments.csv              manifest linking each row of the workbook to the command that produces it
scripts/
  ML - Code/               training of the regression models
  Opt - Code/              optimization algorithms and solution visualization
  setup_data.py            extraction of the optimization instances
  run_experiments.py       execution of the experiments listed in results/experiments.csv
  compare_results.py       comparison of the obtained results with the workbook
output/                    results generated by the scripts (created at run time)
```

-------

*Machine Learning (ML)*

**Data** contains the link to access to the historical dataset and the list of orbits to exclude during training, as they were compromised by solar events. It also contains the dataset for "future" planning, used to generate the predictions and the optimization instances (MARSIS_dataset_2023_2025).

**Code** contains the algorithms setting used to train the five regression models based on scikit-learn package (**Test_KFold.py**) and the keras-based neural network (**Test_KFold_DNN_keras.py**).

-------

*Optimization (Opt)*

**Instances** contains a compressed folder for each of our test instances, named as M_G_L_NC, where G is the granularity of the discretization, L the length of the observation, and NC the number of quality classes, as defined in the article. Each folder contains four .txt files, each corresponding to a different component of the instance:
<ol>
    <li>list of the PIs and related features. Legend of columns:
        <ul>
            <li>Id of the PI</li>
            <li>x<sub>p</sub>: x coordinate (m)</li>
            <li>y<sub>p</sub>: y coordinate (m)</li>
            <li>cov<sub>p</sub>: 1 if PI was already covered in the past; 0 otherwise</li>
            <li>q<sub>p</sub>: initial quality (dB)</li>
            <li>c<sub>p</sub>: initial quality class</li>
            <li>w<sub>p</sub>: 1 if PI belongs to an AOI; 0 otherwise</li>
        </ul>
    </li>
    <li>list of PIs covered by each observation (observation = row)</li>
    <li>list of continuous quality associated to the PIs in each observation (machine learning predictions)</li>
    <li>list of quality classes associated to the PIs in each observation</li>
</ol>

**General** contains files that can be used in combination with each instance. Specifically:
<ul>
    <li> <i> SouthPole_contour.dat </i> : list of (x,y) defining the contour of the South Pole</li>
    <li> <i> AOI*_contour.dat </i> : lists of (x,y) defining the four areas of interest</li>
    <li> <i> day.txt </i> : date of each observation (observation = row)</li>
    <li> <i> orbit.txt </i> : orbit id of each observation (observation = row)</li>
    <li> <i> ephemeris_time.dat </i> : sampled times for future observations; each observation starts at a sampled time and last for at most L seconds</li>
    <li> <i> predictions.txt </i> : machine learning predictions for each sampled time</li>
    <li> <i> x.dat </i> : x coordinate for each sampled time</li>
    <li> <i> y.dat </i> : y coordinate for each sampled time</li>
</ul>

**Code** contains the python code of all the optimization algorithms tested within the research, namely the ILP model (**ILP Model.py**), the Benders decomposition (**Benders.py**), the greedy heuristics (**H1.py**, **H2.py**), the Lagrangian relaxation (**Lagrangian.py**) and the matheuristics of type R, C and G (**Matheuristic_R.py**, **Matheuristic_C.py**, **Matheuristic_G.py**). A further code is included to visualize the solutions (**Visualize_Solution.py**).

***Requirements***
--

All algorithms are coded in Python. The ILP model, the Benders decomposition and the matheuristics require the commercial solver Gurobi (we used version 11.0.1), which needs a valid license (free academic licenses are available at https://www.gurobi.com/academia/). The Python packages required by the scripts are listed in `requirements.txt`.

The experiments were done on a single thread running on an Intel(R) Xeon(R) CPU E5-2640 v3 at 2.60 GHz under Windows 10 Pro with 64 GB RAM. The instances with G = 01 require a large amount of memory: on this machine, the ILP model ran out of memory on most of them.

Storage requirements:

| Content | Size |
|---|---|
| Repository (compressed instances included) | about 300 MB |
| All the 25 instances, extracted | about 21.6 GB (from 18 MB for M_10_067_4 to 4.4 GB for M_01_268_4) |
| Results of all the experiments in `output/` | about 2 GB (about 0.34 MB per solution) |

***Installation***
--

From the root of the repository:

```
python -m venv .venv
source .venv/bin/activate           # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Then extract the instances to be solved, either selected ones or all of them:

```
python scripts/setup_data.py M_10_134_4 M_10_268_4
python scripts/setup_data.py --all
```

Each instance is extracted into `data/Opt - Instances/<instance>/`, which is the location where the optimization codes look for it.

***Quick reproducibility check***
--

The following commands solve four experiments of the paper on the smallest instances (a few minutes in total) and compare the results with the workbook:

```
python scripts/run_experiments.py --id 001 046 086 126
python scripts/compare_results.py
```

The comparison must report `MATCH` for the four experiments:

| Id | Experiment | Expected result | Time |
|---|---|---|---|
| 001 | ILP model on M_10_268_4 | optimal value 2570 | about 30 s |
| 046 | Heuristic H1 on M_10_134_4 | 1882.75 | about 1 s |
| 086 | Heuristic H2 on M_10_134_4 | 1921.5 | about 1 min |
| 126 | Lagrangian relaxation on M_10_134_4 | 1856, upper bound 2064.586 | about 1-2 min |

***Running the optimization algorithms***
--

All the optimization codes take the name of the instance as argument and read the input files from `data/`; the results are saved in `output/` (or in the directory given with `--output-dir`). The default values of all the parameters are those used in the paper, and the full list of options is shown with `--help`. For example:

```
python "scripts/Opt - Code/H1.py" M_10_134_4
python "scripts/Opt - Code/H2.py" M_10_134_4
python "scripts/Opt - Code/ILP Model.py" M_10_134_4
python "scripts/Opt - Code/Benders.py" M_10_134_4
python "scripts/Opt - Code/Lagrangian.py" M_10_134_4
python "scripts/Opt - Code/Matheuristic_R.py" M_10_134_4 R2
python "scripts/Opt - Code/Matheuristic_C.py" M_10_134_4 C3 --N 2
python "scripts/Opt - Code/Visualize_Solution.py" M_10_134_4 output/H1_M_10_134_4.txt
```

The main options are:

| Option | Meaning | Default |
|---|---|---|
| `--N` | number of observations per day | 1 |
| `--W` | scores of the PIs outside and inside an AOI ([1/beta, 1]) | 1 1 |
| `--V` | class quality weights | [0, 0.5, 1] for NC = 3, [0, 0.25, 0.5, 1] for NC = 4, [0, 0.25, 0.5, 0.75, 1] for NC = 5 |
| `--time-limit` | Gurobi time limit (s) | 3600 for the ILP model and Benders, 360 for each subproblem of the matheuristics |
| `--policy` | updating policy of the matheuristics (1-5) | best policy for each granularity: 1 for G = 10, 2 for G = 05, 3 for G = 03, 4 for G = 02, 5 for G = 01 |
| `--n-iter`, `--first-iter` | number of repetitions of the matheuristics and index of the first one (each repetition uses its own random seed) | 20 repetitions, from the first one |
| `--max-time` | time limit of each repetition of the matheuristics (s) | 3600 |
| `--initial-solution` | H2 solution used as initial solution by the Lagrangian relaxation and the matheuristics | `<output-dir>/H2_<instance>.txt` |

***Reproducing the computational results***
--

The file `results/experiments.csv` lists all the experiments reported in `results/Computational Results.xlsx`. Each line corresponds to one command and contains the sheet and rows of the workbook it reproduces, the algorithm, the instance, the parameters (N, W, V, variant, updating policy, repetitions, i.e. random seeds, and time limits), the exact command, the expected output files and the environment used in the paper. The results with N = 1, 2 and 4 are saved in `output/N1`, `output/N2` and `output/N4`, respectively.

The experiments can be run with `scripts/run_experiments.py`, either all of them or a selection by id, sheet, algorithm, instance, variant or N. The missing instances are extracted automatically, and heuristic H2 is run first when its solution is needed as initial solution:

```
python scripts/run_experiments.py --dry-run                                  # print all the commands
python scripts/run_experiments.py --sheet Heuristics Lagrangian
python scripts/run_experiments.py --instance M_10_134_4 --skip-existing
python scripts/run_experiments.py --algorithm Matheuristic --variant R2 --N 1
```

The obtained results can then be compared with the workbook with `scripts/compare_results.py`, which can also save the comparison as a CSV file:

```
python scripts/compare_results.py --report output/comparison.csv
```

H1, H2, the Lagrangian relaxation and the ILP model solved to optimality are deterministic, and their results must coincide with those of the workbook (`MATCH`). The results of the ILP model when the time limit is reached and those of the matheuristics depend on the computing time, and thus on the hardware and on the Gurobi version: for them, the comparison reports the relative difference from the workbook (`TIME-DEPENDENT`).

***Execution order and computational cost***
--

The heuristic H2 must be run before the Lagrangian relaxation and the matheuristics, since they use the H2 solution as initial solution (by default, they read it from `output/H2_<instance>.txt`; `scripts/run_experiments.py` takes care of this automatically):

```
setup_data.py  -->  H1.py, H2.py, ILP Model.py, Benders.py         (independent of each other)
                    H2.py  -->  Lagrangian.py, Matheuristic_R.py, Matheuristic_C.py, Matheuristic_G.py
```

The table below reports the computational effort required to reproduce each sheet of `results/Computational Results.xlsx`, computed from the times reported in the workbook (single thread, hardware described above). All runs are single-threaded and independent of each other, so they can be executed in parallel.

| Experiment (workbook sheet) | Runs | Time limits | Total time |
|---|---|---|---|
| ILP model (*ILP*) | 40 | 3600 s per run | about 24 h (15 runs reach the time limit; 7 runs on G = 01 instances exceed the available memory) |
| Heuristic H1 (*Heuristics*) | 40 | none | about 15 min (at most 2 min per run) |
| Heuristic H2 (*Heuristics*) | 40 | none | about 7.6 h (at most 2 h per run, on M_01_268_4) |
| Lagrangian relaxation (*Lagrangian*) | 40 | none | not reported in the workbook (1-2 min per run on G = 10 instances) |
| Matheuristics R, C and G (*Matheuristic all*) | 5600 (10 or 20 repetitions per configuration) | 3600 s per repetition, 360 s per Gurobi call | about 3900 h |

A single execution of a matheuristic script with the default settings performs 20 repetitions (`--n-iter`) and can therefore take up to about 20 hours.

***Generated files***
--

| Code | Output file | Content |
|---|---|---|
| H1.py, H2.py | `H1_<instance>.txt`, `H2_<instance>.txt` | objective value, number of visited PIs and execution time, followed by the solution |
| ILP Model.py | `ModelSolution_<instance>.txt` | instance parameters, objective value, visited PIs, times, upper bound, gap and explored nodes, followed by the solution |
| Benders.py | `Benders_<instance>.txt` | objective value, visited PIs, times, upper bound, gap and explored nodes, followed by the solution |
| Lagrangian.py | `LagrangianSolution_<instance>.txt` | objective value of the best heuristic solution, visited PIs, time and upper bound, followed by the solution |
| Matheuristic_*.py | `P<policy>_<coeff>_<step>_<variant>_<instance>.txt` | for each repetition: objective value, visited PIs, times, number of iterations and improvement history; at the end: maximum and average values over the repetitions |
| Matheuristic_*.py | `P<policy>_<coeff>_<step>_<variant>(sol)_<instance>.txt` | for each repetition: objective value followed by the solution |
| Visualize_Solution.py | `<solution file name>.pdf` | map of the PIs covered by the solution (in blue those belonging to an AOI) |

Each solution is given by 113,651 lines, one per observation, equal to 1 if the observation is selected and 0 otherwise. When the matheuristics are run on a subset of repetitions, the suffix `_rep<first>-<last>` is added to the file names.

***Machine learning***
--

To train the regression models, first download the historical dataset from the link in `data/ML - Data/MARSIS_historical_dataset` and save it as `data/ML - Data/MARSIS_historical_dataset.csv`. The orbits listed in `data/ML - Data/orbit_to_remove` are excluded from the training. Then, the training scripts can be executed:

```
python "scripts/ML - Code/Test_KFold.py" <model>          # model: linear_regression, knn, decision_tree, gr_boosting, random_forest
python "scripts/ML - Code/Test_KFold_DNN_keras.py"
```

Both scripts perform a 10-fold cross-validation and save in `output/ML/` (or in the directory given with `--output-dir`) the model trained in each fold, the error metrics of each fold and the overall ones, and the predictions for the whole dataset. A different location of the input files can be given with the options `--dataset` and `--orbits-to-remove`.

| Code | Output files | Content |
|---|---|---|
| Test_KFold.py | `MAE_<model>.txt` | train and test indices, MAE, MAPE, MSE and execution time of each fold, and overall MAE, MAPE, MSE and time |
| Test_KFold.py | `<model>_fold<k>.joblib` | model trained in fold k (for KNN and linear regression, together with the fitted standardization) |
| Test_KFold.py | `y_all_pred_noantennas_<model>.txt` | prediction of each sample when it belongs to the test fold |
| Test_KFold_DNN_keras.py | `MAE_nn_chrono.txt` | train and test indices, MAE, MAPE and MSE of each fold with the time elapsed since the start of the cross-validation, and overall MAE, MAPE, MSE and time |
| Test_KFold_DNN_keras.py | `nn_chrono_model_<k>.keras`, `scaler_chrono_<k>.save` | neural network and fitted standardization of fold k |
| Test_KFold_DNN_keras.py | `nn_y_all_pred_chrono.txt` | prediction of each sample when it belongs to the test fold |

***Reproducibility notes***
--

- The neural network is trained without fixing the random seeds of Python, NumPy and TensorFlow, so the trained models and the corresponding metrics are not expected to be reproduced exactly.
- The runtimes depend on the hardware and on the Gurobi version, and they are not expected to match those of the workbook on a different machine.
