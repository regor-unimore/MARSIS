The software and data in this repository are a snapshot of the software and data that were used in the research reported on in the paper "A Predict-then-Optimize Approach for the Research of Underground Water on Mars" by B. Ferrari, M. Delorme, M. Iori, M. Lippi and R. Orosei.

***Description***
--

The material within the data and script folders is divided into "Machine Learning" and "Optimization", to better distinguish the two parts of the proposed predict-then-optimize approach:

```
data/
  ML - Data/               historical dataset (link), orbits to exclude, dataset for the future planning
  Opt - General Data/      general data files, used in combination with each instance
  Opt - Instances/         the 25 optimization instances (one .zip archive per instance)
results/
  Computational Results.xlsx   results reported in the paper
  experiments.csv              manifest linking each row of the workbook to the command that produces it
scripts/
  ML - Code/               training of the regression models
  Opt - Code/              optimization algorithms and solution visualization
  setup_data.py            extraction of the optimization instances
  run_experiments.py       execution of the experiments listed in results/experiments.csv
  compare_results.py       comparison of the obtained results with the workbook
output/                    results generated by the scripts (created at run time)
```

-------

*Machine Learning (ML)*

**Data** contains the link to access to the historical dataset and the list of orbits to exclude during training, as they were compromised by solar events. It also contains the dataset for "future" planning, used to generate the predictions and the optimization instances (MARSIS_dataset_2023_2025).

**Code** contains the algorithms setting used to train the five regression models based on scikit-learn package (**Test_KFold.py**) and the keras-based neural network (**Test_KFold_DNN_keras.py**).

-------

*Optimization (Opt)*

**Instances** contains a compressed folder for each of our test instances, named as M_G_L_NC, where G is the granularity of the discretization, L the length of the observation, and NC the number of quality classes, as defined in the article. Each folder contains four .txt files, each corresponding to a different component of the instance:
<ol>
    <li>list of the PIs and related features. Legend of columns:
        <ul>
            <li>Id of the PI</li>
            <li>x<sub>p</sub>: x coordinate (m)</li>
            <li>y<sub>p</sub>: y coordinate (m)</li>
            <li>cov<sub>p</sub>: 1 if PI was already covered in the past; 0 otherwise</li>
            <li>q<sub>p</sub>: initial quality (dB)</li>
            <li>c<sub>p</sub>: initial quality class</li>
            <li>w<sub>p</sub>: 1 if PI belongs to an AOI; 0 otherwise</li>
        </ul>
    </li>
    <li>list of PIs covered by each observation (observation = row)</li>
    <li>list of continuous quality associated to the PIs in each observation (machine learning predictions)</li>
    <li>list of quality classes associated to the PIs in each observation</li>
</ol>

**General** contains files that can be used in combination with each instance. Specifically:
<ul>
    <li> <i> SouthPole_contour.dat </i> : list of (x,y) defining the contour of the South Pole</li>
    <li> <i> AOI*_contour.dat </i> : lists of (x,y) defining the four areas of interest</li>
    <li> <i> day.txt </i> : date of each observation (observation = row)</li>
    <li> <i> orbit.txt </i> : orbit id of each observation (observation = row)</li>
    <li> <i> ephemeris_time.dat </i> : sampled times for future observations; each observation starts at a sampled time and last for at most L seconds</li>
    <li> <i> predictions.txt </i> : machine learning predictions for each sampled time</li>
    <li> <i> x.dat </i> : x coordinate for each sampled time</li>
    <li> <i> y.dat </i> : y coordinate for each sampled time</li>
</ul>

**Code** contains the python code of all the optimization algorithms tested within the research, namely the ILP model (**ILP Model.py**), the Benders decomposition (**Benders.py**), the greedy heuristics (**H1.py**, **H2.py**), the Lagrangian relaxation (**Lagrangian.py**) and the matheuristics of type R, C and G (**Matheuristic_R.py**, **Matheuristic_C.py**, **Matheuristic_G.py**). A further code is included to visualize the solutions (**Visualize_Solution.py**).

***Requirements***
--

- Python 3.8.10 with the packages listed in `requirements.txt` (these versions support Python 3.8-3.10).
- Gurobi 11.0.1, included in the `gurobipy` package, with a valid license (free academic licenses: https://www.gurobi.com/academia/).
- About 22 GB of disk space to extract all the instances.

The experiments were run on a single thread of an Intel(R) Xeon(R) CPU E5-2640 v3 at 2.60 GHz with 64 GB RAM, under Windows 10 Pro.

***Installation***
--

```
python3.8 -m venv .venv                  # on Windows: py -3.8 -m venv .venv
source .venv/bin/activate                # on Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/setup_data.py --all       # or only some instances, e.g. M_10_134_4
```

***Quick check***
--

The following commands run four experiments of the paper (a few minutes in total) and compare them with the workbook; all of them must be reported as `MATCH`:

```
python scripts/run_experiments.py --id 001 046 086 126
python scripts/compare_results.py
```

***Running the optimization algorithms***
--

Each code takes the name of the instance (and the variant, for the matheuristics) and saves the results in `output/`. The default parameters are those of the paper; all the options (e.g., `--N`, `--W`, `--policy`) are listed with `--help`.

```
python "scripts/Opt - Code/H2.py" M_10_134_4
python "scripts/Opt - Code/ILP Model.py" M_10_134_4
python "scripts/Opt - Code/Matheuristic_R.py" M_10_134_4 R2
python "scripts/Opt - Code/Visualize_Solution.py" M_10_134_4 output/H2_M_10_134_4.txt
```

Note that the Lagrangian relaxation and the matheuristics start from the solution of H2, which must therefore be run first.

***Reproducing the computational results***
--

`results/experiments.csv` links each row of `results/Computational Results.xlsx` to the command and parameters (N, W, V, variant, policy, seeds, time limits) that produce it. The experiments can be run, all or a selection, and then compared with the workbook:

```
python scripts/run_experiments.py --sheet Heuristics     # selection also by --id, --instance, --algorithm; --dry-run only prints the commands
python scripts/compare_results.py
```

H1, H2, the Lagrangian relaxation and the ILP model solved to optimality must match the workbook exactly. The ILP model at the time limit and the matheuristics depend on the computing time, so only their difference from the workbook is reported.

Computational effort on the hardware above (all runs are single-threaded and can be executed in parallel):

| Workbook sheet | Runs | Total time |
|---|---|---|
| ILP | 40 | about 24 h (3600 s time limit per run) |
| Heuristics | 80 | about 8 h |
| Lagrangian | 40 | about 1-2 min per run on G = 10 instances |
| Matheuristic all | 5600 | about 3900 h (up to 1 h per run) |

***Machine learning***
--

Download the historical dataset from the link in `data/ML - Data/MARSIS_historical_dataset`, save it as `data/ML - Data/MARSIS_historical_dataset.csv`, and run:

```
python "scripts/ML - Code/Test_KFold.py" knn     # or linear_regression, decision_tree, gr_boosting, random_forest
python "scripts/ML - Code/Test_KFold_DNN_keras.py"
```

The models of each fold, the error metrics and the predictions are saved in `output/ML/`.

***Reproducibility notes***
--

- The random seeds of the neural network are not fixed, so its models and metrics are not expected to be reproduced exactly.
- Runtimes depend on the hardware and on the Gurobi version.
